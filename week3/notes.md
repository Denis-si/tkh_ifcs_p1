# Week 3 — Security Automation with Python

**TKH Innovation Fellowship 2026 | Phase 1 | Cybersecurity**

## What I Learned

This week focused on engineering custom security tools and automated pipelines using Python to dramatically decrease incident response times. The core technical skills centered around writing scripts that leverage native libraries like `socket` for network reconnaissance, `subprocess` for system process auditing, and `json` for data serialization. These automation capabilities directly reinforce the security principles of rapid threat detection and consistent security operations, proving how software-defined security minimizes human error and scales defense capabilities across enterprise environments.

## Artifacts

* **port_check.py** A network utility built using Python's raw socket programming library to scan target hosts and identify active network services. I wrote this script to handle connection timeouts and accurately map open, closed, or filtered network ports.
* **brute_detector.py** An automated text-parsing script designed to ingest raw system authentication logs, analyze baseline behavior, and flag active brute-force attacks. I built this tool to dynamically track failed login thresholds and isolate offending user accounts.
* **brute_report.txt** A clean text output file summarizing the anomalies flagged by the brute-force detector. I generated this to provide a human-readable log of malicious login attempts and security events.
* **system_auditor.py** A system security script that uses automated command execution to audit running processes, resource usage, and active connections. I engineered this tool to parse OS-level process tables and immediately alert on unauthorized or hidden binaries.
* **security_alert.json** A standardized, machine-readable alert file detailing high-risk process anomalies discovered during system auditing. I formatted this output in JSON to ensure seamless integration with downstream SIEM and alerting platforms.
* **incident_response.py** An end-to-end orchestration script that fuses log analysis with automated threat intelligence generation. I developed this program to automatically extract attacker IPs from logs and package them into structured security intelligence.
* **threat_report.json** The final structured data product generated by the incident response pipeline containing validated Indicators of Compromise (IOCs). This artifact was built to automate the sharing of actionable threat intelligence with network defensive teams.

## Challenges & How I Solved Them

A critical bottleneck occurred when developing the log analysis tools, as processing massive text files line-by-line using unoptimized loops resulted in high CPU usage and slow execution times. To solve this, I refactored the string manipulation logic in `brute_detector.py` and `incident_response.py` to utilize efficient data structures and conditional filters, ensuring the scripts could process log streams rapidly without crashing. Another issue arose when handling varying data types from `subprocess` outputs; I resolved this by enforcing explicit string decoding (`utf-8`) and handling data exceptions gracefully to prevent the security pipeline from breaking during unexpected system states.

## Reflection

This week's milestones demonstrate that scripting is a mandatory force multiplier for any modern cybersecurity engineer. Shifting from manual log analysis to programmatic detection proves that capturing and formatting threat data automatically is the only way to keep pace with modern adversaries. In future development cycles, I plan to incorporate multi-threading into my socket-based tools to significantly improve scanning efficiency over wider network ranges.
